Sonorium has an HTTP API with JSON bodies. Everything the web UI does goes through it, so anything you can do on a screen, a program can do too: start a channel when the alarm goes off, duck the music for a doorbell chime, change the theme from a wall tablet, follow what plays from a dashboard.

Who uses it:

  • Home Assistant automations and scripts (rest_command), next to the MQTT entities Sonorium already gives Home Assistant.
  • Node-RED flows (the http request node, and the event stream for triggers).
  • Scripts (curl, Python, PowerShell) and other programs: dashboards, bots, wall panels, ESP32 buttons.

This page describes Sonorium 1.7.1. The complete reference, with every field the Android app uses, is docs/APP_API.md in the repository; sign-in is in docs/AUTH.md. To extend Sonorium from the inside, see Plugin Development.

Base URL and ports

Port Protocol What it serves
8008 HTTP Web UI, API, audio streams. Speakers fetch their streams here.
8808 HTTPS The same web UI and API, encrypted, with Sonorium's self-signed certificate.

Every API path starts with /api:

http://192.0.2.20:8008/api/sessions
https://192.0.2.20:8808/api/sessions
  • Home Assistant app: use the Home Assistant machine's address. 8008 and 8808 are the app's Network mappings (8008 is port 8080 inside the container); change them on the app's Network tab. Home Assistant's sidebar link is for people signed in to Home Assistant; programs use the direct ports.
  • Docker: host networking serves both ports on the host. SONORIUM_HTTPS_PORT changes 8808.
  • Docker and Windows/Linux installs announce sonorium.local on the network (mDNS), so http://sonorium.local:8008 works without knowing the address. When another device already has that name, Sonorium is sonorium-2.local (up to sonorium-9.local); the log says which name it got. The Home Assistant app doesn't announce a name.

The HTTPS certificate

Sonorium makes its HTTPS certificate on first start and keeps it for 20 years (ECDSA P-256, self-signed). No public authority signed it, so a browser warns about it and a program has to be told to trust it. The certificate names sonorium.local to sonorium-9.local, localhost, 127.0.0.1 and the network addresses the server had when the certificate was made.

Think of the fingerprint as the certificate's serial number: if the number you see matches the one Sonorium reports, you are talking to your Sonorium.

To trust it with curl:

  1. Save the certificate:
    openssl s_client -connect 192.0.2.20:8808 </dev/null 2>/dev/null | openssl x509 -outform PEM > sonorium.pem
  2. Print its fingerprint:
    openssl x509 -in sonorium.pem -outform DER | sha256sum
  3. Compare it with fingerprint from GET /api/info. They must be the same.
  4. Call the API with the saved certificate, using a name the certificate lists:
    curl --cacert sonorium.pem -H "Authorization: Bearer $KEY" https://sonorium.local:8808/api/sessions

On Windows (PowerShell), step 2 is Get-FileHash -Algorithm SHA256 on the DER file; the result is uppercase, the same digits.

Plain HTTP on 8008 is fine on a home network you trust. Keys and passwords sent over 8008 can be read by anyone who can watch that network; use 8808 when that matters.

Authentication

Who may call the API depends on the Users plugin's Require login (Settings › Users & devices):

Require login A call without a key
Off (or the Users plugin is off) Allowed: Sonorium is open to anyone on the network, as before sign-in existed. A key still limits what its caller may do when one is sent.
On Refused with 401, except GET /api/info, the sign-in routes and the audio streams.

Webhook triggers and the event stream always need a key or a token, whether Require login is on or off.

Keys

A key is a password for a program. It allows only the items checked on it, and it can be limited to some channels. Keys start with sk_. A key never manages users or keys.

Making a key (an Admin):

  1. Open Settings in the left menu.
  2. Click Keys.
  3. Click New key (top right).
  4. Type a Name, such as Kitchen tablet.
  5. Pick Expires: In 7 days, In 30 days, In 90 days (the default), In 1 year or Never.
  6. Check what the key may do (the boxes are listed under Abilities).
  7. Under Channels, leave All channels, or click Only these… and check the channels.
  8. Click Make key.
  9. In Key issued, click Copy, then Done. The key is shown once; Sonorium keeps only a hash of it.

⋯ › Edit… changes the name, expiry and boxes; the change applies from the key's next request. ⋯ › Revoke… stops the key at once.

Sending a key, any one of:

Authorization: Bearer sk_EXAMPLE0000000000000000000000000000000000
X-Sonorium-Token: sk_EXAMPLE0000000000000000000000000000000000
?token=sk_EXAMPLE0000000000000000000000000000000000

Use a header. The query form is for devices that can only open a URL; Sonorium masks token= in its log.

KEY=sk_EXAMPLE0000000000000000000000000000000000
curl -H "Authorization: Bearer $KEY" http://192.0.2.20:8008/api/sessions

GET /api/auth/me shows what the key may do:

Other callers

Caller How it is recognised What it may do

A linked phone (the Sonorium app) Authorization: Bearer sd_… Its user's role, less managing users, devices and keys

Browsers and the CSRF token. A program can sign in like a browser: POST /api/auth/login with {"username", "password"} sets the sonorium_session cookie (HttpOnly, SameSite=Strict, Secure on HTTPS). Every change (POST, PUT, DELETE) with that cookie must carry the X-CSRF-Token header, whose value is csrf from GET /api/auth/me; without it the answer is 403 {"detail": "Reload the page and try again", "csrf": true}. A session lasts 30 days, or until it is 14 days unused. Calls with a key or a phone token need no CSRF token. For programs, a key is simpler.

Permissions no key can have: admin.users (users), admin.keys (keys and the older trigger and event-stream tokens), admin.plugins (installing and configuring plugins, schedules, command maps), admin.connection (Settings › Connection), self (linking a phone, your own phones) and device (only a linked phone).

Channel limits. A key limited to some channels (Only these…) sees only those channels in GET /api/sessions and GET /api/now-playing. A channel route for another channel answers 403 {"detail": "Not allowed for this channel"}. Routes that change channels without naming one (creating a channel, stop all) answer 403 {"detail": "Only allowed for some channels"}. POST /api/announce with "all" means the key's channels.

Requests, answers and errors

  • Request bodies are JSON objects, sent with Content-Type: application/json. Uploads are multipart/form-data.
  • Times are ISO 8601. Most are UTC (+00:00); a channel's created_at and last_played_at are local time without an offset.
  • Unknown fields in answers can appear in later versions: ignore what you don't know.

Errors have an HTTP status and a body:

{"detail": "Session not found"}

A body that fails validation answers 422 with a list:

{"detail": [{"type": "less_than_equal", "loc": ["body", "volume"], "msg": "Input should be less than or equal to 100", "input": 200, "ctx": {"le": 100}}]}
Status Body When
400 {"detail": "…"} A bad value, Invalid JSON body, Expected a JSON object
401 {"detail": "This key is not valid. It may have expired or been revoked."} A wrong, expired or revoked key
401 {"detail": "Sign in first", "login": true} No key, and sign-in is required
401 {"detail": "A valid token is needed"} Triggers and the event stream without a key or token
403 {"detail": "Not allowed"} The key lacks the ability; also any /api/… path Sonorium doesn't have
403 {"detail": "Only an admin can do this"} A User's sign-in or phone on an Admin route
403 {"detail": "Not allowed for this channel"} A channel outside a key's channels
403 {"detail": "Not allowed from another site"} A browser request from another web site without a key
404 {"detail": "Session not found"} and similar Unknown id
404 {"detail": "Not Found"} A route of a plugin that is switched off
409 {"detail": "…"} A conflict: a duplicate name, no free channel slot, nothing to skip, a busy speaker, a group in use
422 a list, as above A field out of range or of the wrong type
429 {"detail": "…"} + Retry-After Rate limited
502 {"detail": "…"} A plugin, a speaker or text to speech failed
503 {"detail": "Sonorium is starting", "starting": true} Retry in a few seconds

Theme, category and /api/channels routes answer errors with both keys, {"detail": "Theme not found", "error": "Theme not found"}, with the status chosen from the message: 404 "… not found", 409 "… already exists", 503 "… not available", 500 "Failed …", else 400.

Rate limits

What Limit Answer
Webhook trigger calls 10 in a burst, then 2 a second, per trigger 429, Retry-After
Wrong trigger tokens 10 from one address, then one every 6 s 429, Retry-After
Sign-in (/api/auth/login, /api/pair/login) 5 failures a minute from one address 429, Retry-After
Phone linking (/api/pair) 5 in a burst, then one every 12 s, per address 429, Retry-After
Event streams open at once 20 per server 503 Too many event streams open
Everything else none

Limits are kept in memory: a restart clears them.

Live events

Sonorium announces what happens as events: a channel started, its volume changed, a sequence moved to its next step, a speaker went offline. A program follows them as Server-Sent Events, a long HTTP answer that never ends, one event at a time, like a news ticker. Use it instead of asking for /api/sessions every few seconds.

GET /api/events/stream · ev.read (Read events)

Query Default Meaning
types * Comma-separated patterns: a type (channel.started), a prefix (channel.*) or *
last_event_id Replay the events after this id (same as the Last-Event-ID header)
max_events 0 Above 0: close the stream after that many events 
curl -N -H "Authorization: Bearer $KEY" "http://192.0.2.20:8008/api/events/stream?types=channel.*,sound.*"

What arrives:

retry: 5000

id: d10435418d284eea8d9f6cdfbd0251be:12
event: channel.started
data: {"id": 12, "boot_id": "d10435418d284eea8d9f6cdfbd0251be", "type": "channel.started", "time": "2026-10-12T16:17:39.796333+00:00", "origin": "sonorium", "data": {"channel_id": "2c62267b", "name": "Kitchen", "theme_id": "df297db5-a98d-4372-8029-2c49d1e280e4", "preset_id": "slow_night_at_the_inn", "volume": 40, "speakers": ["net:dlna:fake-10"]}}

id: d10435418d284eea8d9f6cdfbd0251be:15
event: channel.changed
data: {"id": 15, "boot_id": "d10435418d284eea8d9f6cdfbd0251be", "type": "channel.changed", "time": "2026-10-12T16:17:41.983708+00:00", "origin": "sonorium", "data": {"channel_id": "2c62267b", "name": "Kitchen", "changes": {"speakers_muted": true}}}

: keep-alive
  • Each event has id, boot_id, type, time (UTC), origin and data. origin is sonorium (the web UI, the API, Home Assistant, timers) or plugin:<id>.
  • In events, channel_id is the channel's id (the id of /api/sessions).
  • A : keep-alive line comes every 15 s. Treat 45 s of silence as a lost connection.
  • retry: 5000: reconnect after 5 s. Send the last id: you received as Last-Event-ID (or ?last_event_id=) and Sonorium replays the events since then that it still holds (the last 200), then goes on live.
  • The id is <boot_id>:<n>. n starts again at 1 when Sonorium restarts. An id from before a restart replays every event of the new run Sonorium still holds; when boot_id changes, read the state again (GET /api/sessions).
  • A reader that falls more than 500 events behind loses the oldest.
  • Errors: 401 no or wrong key, 400 a bad pattern, 503 too many streams open.

Browsers' EventSource can't send headers: use ?token= there.

The event stream also accepts an older token made for it alone: POST /api/events/token (Admin) answers {"token": "…"} once and replaces the previous one; GET /api/events/token says whether one is set; DELETE /api/events/token revokes it. A key with Read events does the same job.

Channels

A channel is what you create on the Channels page: a theme, a preset or sequence, speakers and a volume. In the API a channel is a session (/api/sessions, session_id, 8 hex characters such as 2c62267b). Separately, /api/channels lists numbered stream slots (/stream/channel1…); a channel borrows a slot while it plays. Use /api/sessions.

Creating and changing a channel

POST /api/sessions and PUT /api/sessions/{id} take the same fields; all are optional.

Sounds play over a channel's mix: the channel's sound ducks (gets quieter), the sound plays, the channel comes back, like a radio presenter talking over the music. Every speaker, browser and cast device of the channel hears it.

Audio streams

Path What it plays
/stream/channel{N} A channel's stream slot (N = 1 to max_channels, 6 by default). N is the channel's channel_id, or comes from stream_path of listen.
/stream/channel{N}?local=1 The same, as a listener: keeps the mix running without speakers, and is heard while the speakers are muted
/stream/{theme_id} A theme with the settings saved in it (previews)
  • No key: speakers can't sign in. Anyone on the network can listen to a channel that plays; changing anything needs the API.
  • MP3, 44.1 kHz, mono, 128 kbps, chunked, no length and no seeking. Each listener joins at the live point.
  • A slot that isn't playing answers 200 with no audio. POST /api/sessions/{id}/listen starts it first.
  • Use port 8008: Cast devices and most speakers refuse a self-signed HTTPS address.

Home Assistant: a rest_command

Sonorium's MQTT entities already cover play, stop, volume, theme and preset (MQTT Entities). The API adds what entities don't: announcements with options, ramps, playlists. In configuration.yaml (the key is in secrets.yaml as sonorium_key: "Bearer sk_…"):

rest_command:
  sonorium_announce:
    url: "http://192.0.2.20:8008/api/announce"
    method: post
    headers:
      Authorization: !secret sonorium_key
    content_type: "application/json"
    payload: '{"channels": {{ channels | tojson }}, "text": {{ text | tojson }}, "volume": 90}'
  sonorium_sleep_timer:
    url: "http://192.0.2.20:8008/api/sessions/{{ channel_id }}/ramp"
    method: post
    headers:
      Authorization: !secret sonorium_key
    content_type: "application/json"
    payload: '{"to": 0, "seconds": {{ minutes * 60 }}, "then": "stop"}'

In an automation:

action: rest_command.sonorium_announce
data:
  channels: ["Kitchen", "Living Room"]
  text: "The laundry is done"

The key needs Make announcements, and Channels: Change theme, preset and volume for the ramp.

Python

import json
import urllib.request

BASE = "http://192.0.2.20:8008/api"
KEY = "sk_EXAMPLE0000000000000000000000000000000000"


def call(method, path, body=None):
    data = None if body is None else json.dumps(body).encode()
    request = urllib.request.Request(BASE + path, data=data, method=method,
                                     headers={"Authorization": f"Bearer {KEY}", "Content-Type": "application/json"})
    with urllib.request.urlopen(request) as answer:
        text = answer.read()
        return json.loads(text) if text else None


kitchen = next(c for c in call("GET", "/sessions") if c["name"] == "Kitchen")
call("POST", f"/sessions/{kitchen['id']}/volume", {"volume": 30})
call("POST", f"/sessions/{kitchen['id']}/play")
